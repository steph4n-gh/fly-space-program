# Serious work. Very small flight crew.

Fly Space Program is an attempt to push fly-derived control as far as simulation can take it, then leave a clear account of what a physical experiment would need to establish. We want the software to invite exploration, the research to withstand scrutiny, and the little fly to make you smile.

## The Omarchy influence

We draw inspiration from the [Omarchy Doctrine](https://omarchy.org/doctrine/): care about the work and its craft, make room for humor, respect the people who built the foundations, welcome useful agent contributions, and give a project a coherent direction. Beautiful interfaces can make difficult technical work more inviting. A strong default can coexist with inspectable, changeable code.

Those ideas guide our application to this project; we do not claim affiliation or endorsement. Our license choice also differs from Omarchy's open-source ideal. Fly Space Program uses the person-excluding [No Theo License](LICENSE), so its code is described as source-available.

## Seven commitments

| Virtue | What it asks of this project |
| --- | --- |
| **Honor** | Keep commitments. Credit the anatomical data, experimental work and software we build upon. |
| **Strength** | Stay with hard problems and maintain a system that people can inspect and improve. |
| **Courage** | Try ambitious ideas and report when the results contradict the hope. |
| **Duty** | Preserve provenance, reproducibility and the distinction between a demonstration and evidence. |
| **Justice** | Judge contributions and scientific claims fairly, by their substance and evidence. |
| **Beauty** | Treat the interface, diagrams, prose and implementation as parts of the same craft. |
| **Truth** | Keep failures visible. State assumptions. Never let a compelling image stand in for an experiment. |

## How that changes the work

Choose the simplest implementation that satisfies a demonstrated need. Measure improvements on the same conditions, preserve every outcome, and distinguish development cases from final tests. Agent-generated code and prose receive the same scrutiny as any other contribution; an agent's confidence is not verification.

The fly's expressions and command-center jokes are deliberately theatrical. The graph calculations and reports are inspectable. The Fly Cube is speculative hardware, and learning in a simplified model does not establish learning in a living animal. We can keep the ambition large without quietly moving those boundaries.

Public availability invites scrutiny and contributions. It does not establish scientific completion; the claims still have to earn their evidence.
